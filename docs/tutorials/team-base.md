# 📚 Build a shared team base

Combine a team, claim rules and shared destinations for a settlement.


**Uses:** [Teams](/players/teams), [Claims](/claims/getting-started), [Subclaims](/claims/subclaims), [Waypoints](/players/waypoints).

## 📌 1. Form the team

Create your team and invite the intended players. Have them accept before testing team access. Assign team admins only to people who should manage members and destinations.

## 📌 2. Claim the land

Use a Claim Flag for a single chunk or two sneak-used corners. Confirm you have enough Claim Allowance for the complete selection. Rename the main claim so members can recognise it.

## 📌 3. Share only the intended actions

For the main claim's editable building, breaking and interaction rules, choose **Team** where you want current teammates allowed. Check each action separately. Keep visitor access restricted where appropriate.

Team audiences follow the **main claim owner's current team**. If ownership or membership changes, access can change immediately. Other matching denies and forced realm policy still apply.

## 📌 4. Add private plots

Create subclaims for workshops or homes. Give each the needed trusted players and rules. A subclaim has its own trusted list, but a Team audience still refers to the main owner, not a new independent team.

## 📌 5. Add navigation and travel

Set a team home and shared team warps where permitted. Add a team waypoint so members can navigate without teleporting. A player warp's Allow Team option is a different, owner-managed way to share a destination.

## ✅ 6. Test the boundaries

Ask one teammate and one outsider to try a chest, a build action and a shared destination. Then test a departing member. Check locks separately: team claim access does not automatically add someone to a lock's trusted list.
