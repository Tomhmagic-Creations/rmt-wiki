# 🧭 Player Warps

Publish a destination for visitors or restrict it to your current teammates.


## 📌 Create a destination

1. Stand at the location you want visitors to reach.
2. Open **Player Warps** and use the add option.
3. Enter a readable name, description and category, then save.
4. Test it and ask a second player to confirm the intended audience can use it.

The initial ordinary limit is five player warps. Creating or relocating one must be permitted by the claim's Set Warp rule. A display name can change while the warp's permanent ID stays the same.

## 🗂️ Help visitors find it

Categories include Farming, Mining, Shop, Arena, Mob, Building, Resources, POI and Other. Use a description that explains what visitors can do there. Browse by category or name and use the offered vote/name sorting. Visitors can vote through the available menu controls.

## 🔐 Allow Team

Enable **Allow Team** if the destination should be limited to you and your current teammates. This restricts the same warp; it does not create a separate copy. If you have no team, there is no teammate audience. Leaving or changing teams changes who qualifies.

This is different from a team-owned shared warp, which the team's owner/admins manage in team features.

## ⌨️ Travel by ID

```text
/thm_rmt:playerwarp "Owner Name" warp_id
```

Replace both values with the actual owner and saved ID. The alias is `pwarp`. A renamed display label is not necessarily the permanent ID.

## ✅ Maintain the destination

Check the arrival point when rebuilding your area. Moving, deleting or restricting a warp during a warm-up can cancel that trip. Access, membership and the saved destination are rechecked at arrival time. A public warp does not grant visitors building or container access through your claim rules.
